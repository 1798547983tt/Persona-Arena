# 0004 行动输出契约：`<move>` 与 `<state>` 双标签，而不是纯 JSON

日期：2026-09-24 · 状态：已采用

## 背景

需要从一次生成里同时拿到"角色的行动文本"和"面板更新（心情/目标/羁绊/经历）"。可选：
1. 要求整段输出为 JSON；
2. 两次调用（行动一次、反思一次）；
3. 标签分段：`<move>…</move>` 放行动，`<state>{…}</state>` 放 JSON。

## 决定

采用方案 3。解析规则（`src/llm.js`）：
- 取第一个 `<move>…</move>` 内容为行动；没有闭合标签时取 `<move>` 之后到 `<state>` 之前；完全没有标签时取全文；
- `<state>` 内容做宽松 JSON 提取（第一个 `{` 到最后一个 `}`），失败则忽略；
- 行动超过长度上限时按句截断并加省略号。

## 理由

- 角色扮演向的模型对纯 JSON 遵从度差，一个引号错误就丢掉整条行动；标签分段让行动文本永远可用。
- 一次调用省一半成本与延迟；顺序模式下演员多，延迟是主要体验瓶颈。

## 代价

- 面板更新是"尽力而为"，偶尔缺失；玩家可手动编辑面板兜底。
